## 1. 项目概述

心屿面向“疲惫、焦虑、失眠、需要倾诉”这类高频但低门槛的心理陪伴需求。用户打开页面即可进入对话，可以用文字、语音或图片表达，AI 的回复可以带情绪地朗读出来；情绪持续低落时，页面提供正念呼吸和每日能量站两个轻量模块承接。数据默认留在浏览器本地，云备份单独加密。

项目的技术投入集中在四个方向：让语音合成跟上流式生成节奏、让图片输入在模型能力不足时自动降级、让对话可以分支对比、让不可控的上游服务变成可控的后端能力。下面按创新点和独有功能展开，功能清单放在使用方式一节。

## 2. 核心创新点

### 2.1 模型自主标注情绪，前端句子级流水线合成语音

**问题**：传统 TTS 接入方式是把整段回复生成完再合成，用户要等文本结束才听到第一句；情绪通常由用户在设置里手动选，和回复内容脱节。

**做法**：

系统提示词要求模型在每次回复开头输出一次情绪标签，包含情绪类别、权重和语言。标签对用户不可见，正文不出现标签、不提语音和情绪。

前端维护原始缓冲与可见文本，逐块剥离标签得到可见文本，再按中英文句末标点和长度上限切句。

每切出一句立即发起合成请求，合成结果进入提交链和播放链，分别保证文本按序显示、音频按序播放。用户听到第一句时，后续句子可能仍在生成。

合成失败时该句降级为纯文本提交，对话不中断；用户点停止时取消后续合成并释放已生成的音频资源，避免资源泄漏。

**为什么这样设计有效**：情绪由模型根据回复内容给出，和文本语义一致；句子级并行把“首句可听时间”从“整段生成完”压缩到“第一句生成完”；两条链分离保证文本显示顺序和音频播放顺序都不乱。8 维情绪向量由服务端映射为语音合成控制参数，链路中不丢失信息。

### 2.2 图片输入的能力探测与自动降级重试

**问题**：多模型接入后，用户不一定知道当前模型是否支持视觉输入；直接报错会让用户卡住。

**做法**：

前端通过上游错误特征识别当前模型是否不支持图片输入。

识别到图片不支持时，自动开启 OCR、回滚到该条用户消息节点、用图片文字重新发送，并提示用户“已自动开启 OCR，正在改用图片文字重试”。

回滚时把当前叶节点指回父节点，重发时生成新分支，原始失败节点保留在对话树里可查。

OCR 走本地浏览器 worker，语言包为中文简体加英文，识别进度实时显示；识别失败回退到文件摘要。

**为什么这样设计有效**：把“模型能力不确定”变成一个可恢复的工作流，用户不需要理解视觉模型和 OCR 的区别；失败节点不删除，用户可以在对话树里看到原始尝试；OCR 完全在浏览器执行，图片不出本机。

### 2.3 对话树支撑的编辑、撤回与重新生成

**问题**：线性聊天记录里，用户改一句话就丢失原对话；重新生成会覆盖上一条回答，无法对比。

**做法**：

消息节点带父节点标识，会话带当前叶节点标识。当前显示消息从叶节点沿父节点回溯到根得到。

编辑用户消息时以原节点的父节点为父创建新节点，形成兄弟分支；撤回时把叶节点指向父节点；重新生成时基于同一用户节点的父节点生成新的助手兄弟节点。

对话树组件用深度优先展开整棵树，标记当前路径，显示兄弟序号，支持在树内直接编辑、撤回、重新生成。

所有节点变更写入本地数据库，刷新后树结构完整恢复。

**为什么这样设计有效**：分支是数据模型中的基础实体；编辑和重生成都会产生新节点，不覆盖旧节点；用户可以在树结构中横向对比同一问题的多个回答，再决定保留哪条路径；单字段切换路径，读取成本低。

### 2.4 试用访问与配额管理

**问题**：评审或新用户需要低成本试用；直接暴露上游服务会被滥用，直接要求注册会挡住体验。

**做法**：

系统提供轻量试用入口，发放短期试用凭证。凭证由服务端校验签名与有效期，不依赖服务端保存会话，过期后自然失效。

试用请求按凭证维度进行时间窗口配额管理，超出配额时返回明确提示，前端可引导用户稍后重试或前往设置页。

前端自动检测试用状态，未授权时提示申请，申请成功后记住状态，避免重复申请。

服务端对过期、无效、配额用尽等情况返回可区分的错误语义，便于前端处理。

**为什么这样设计有效**：试用凭证可校验且不依赖服务端会话；配额按凭证维度计数，评审多人共用一台机器也能各自计数；前端能区分“未申请”和“配额用尽”，体验不中断。

### 2.5 语音合成服务的稳定性与资源管理

**问题**：语音合成上游并发能力有限；直接透传会让请求堆积、超时不可控、临时资源泄漏。

**做法**：

服务端对语音合成请求做排队与限流，严格按先来先服务处理；队列满时返回明确错误，避免请求无限堆积。

合成请求设置超时控制，超时后取消任务并返回可识别错误；管理员可清理排队任务，便于运维恢复。

合成结果按需获取并缓存，临时资源在请求或流式响应结束后清理，避免磁盘增长。

服务端记录提交、完成、失败、取消等状态，并提供健康状态供运维观察待处理数量和统计信息。

**为什么这样设计有效**：上游不稳时不把压力透传给用户，而是用明确的错误语义告诉前端发生了什么；服务端排队保证语音合成服务不会被并发打满；临时资源在生命周期结束点清理，避免资源增长。

### 2.6 本地优先的数据边界与独立加密的云备份

**问题**：心理陪伴内容敏感；用户既希望数据留在本地，又需要换设备时能恢复。

**做法**：

对话、消息、附件摘要存浏览器本地数据库，自定义音色 Blob 单独存储，API Key 只存本地存储，全部不上传。

云备份需要登录，另设独立加密密码：先压缩再加密，服务端只存密文；拉取时本地解密，按会话标识去重导入。

加密密码只存在内存，上传/拉取成功或关闭抽屉后清空，不写入任何存储。

上传前自动剔除空会话；删除服务器备份和清空本地数据是两个独立危险操作，各自二次确认。

**为什么这样设计有效**：账户密码和加密密码分离，服务端即使被登录也无法解密密文；本地数据是主副本，云备份是可选副本，清空本地不影响云端；空会话过滤避免把无意义数据传到服务端。

## 3. 独有功能与使用方式

### 3.1 首次使用流程

1. 打开页面进入聊天主界面，顶部可切换“跟随系统/浅色/深色”。
2. 打开“设置 → 模型”，从内置 Provider 选择或添加自定义 OpenAI/Anthropic 兼容端点，选中模型。
3. “设置 → 语音”启用 TTS，选择预设音色，或上传 3–15 秒参考音频添加自定义音色，点“试听当前音色”确认。
4. 在聊天框输入文字，或用语音按钮按住说话/单击锁定；可上传图片，用“OCR 开/关”决定发图片还是发图片文字。
5. 消息下方操作栏可编辑、撤回、重新生成；右侧对话树可切换分支。
6. “设置 → 云备份”登录后输入独立加密密码，上传或拉取。

## 4. AI 技术落地使用情况

### 4.1 LLM 集成

通过统一 LLM 接入层创建客户端，流式返回异步迭代器，逐块消费。

自定义端点通过自定义 Provider 注册，兼容主流对话协议，配置写入服务地址、API Key 和默认模型。

历史构建沿父节点回溯，附件摘要拼进文本，图片按多模态内容块发送，支持 system/user/assistant 角色。

Prompt 分三层：应用级、用户级（持久化到本地存储）、会话历史；TTS 开启时追加情绪标签指令。

### 4.2 多模态输入

| 模态     | 路径与降级                                         |
| -------- | -------------------------------------------------- |
| 文本     | LLM 流式，错误写入节点并持久化                     |
| 图片     | 视觉模型多模态输入 → 不支持时自动 OCR + 回滚重发   |
| 语音输入 | Web Speech API → 浏览器不支持时提示 Chrome/Edge    |
| 语音输出 | 语音合成服务 + 情绪向量合成 → 失败保留文本，可停止 |
| OCR      | Tesseract.js 本地 worker → 失败回退文件摘要        |

### 4.3 可控性与安全

- 语音合成管理接口与试用访问均使用安全校验；试用凭证带签名与有效期，配额按凭证维度限制。
- API Key 只存本地存储；云备份独立加密密码只存内存；上传临时文件和语音合成临时资源在请求/流结束后清理。
- 服务端对队列满、超时、取消等返回明确错误语义，前端可区分处理。

## 5. 关键技术

1. **Vue 3 Composition API + 组件化**：聊天主界面编排，设置抽屉、对话树、音色选择、语音输入、能量站、正念呼吸等组件职责分离。
2. **流式状态管理**：通过流式组合式函数创建助手节点，增量写入内容，生成带父节点标识的节点。
3. **对话树模型**：父节点标识 + 当前叶节点标识，当前消息计算属性回溯路径，切换节点时沿最新子节点下钻。
4. **本地数据库仓库**：会话仓库管理对话、消息、附件，音色仓库管理音色 Blob，导入导出按会话标识去重。
5. **TTS 参数映射**：服务端将 8 维情绪向量映射为语音合成控制参数，并按合成服务要求适配生成参数。
6. **句子级流水线**：切句函数按标点和长度切分，提交链/播放链双链保证顺序，取消标志和音频资源释放处理取消。
7. **服务端能力抽象**：语音合成服务代理、试用访问代理、通用请求代理；排队、限流、超时与资源清理机制。
8. **安全机制**：试用凭证签名校验、安全 Cookie、时间窗口配额回收、云备份加密。
9. **前端体验**：CSS 变量主题、减少动效适配、响应式媒体查询、事件委托处理消息操作栏、OCR 进度条、TTS 播放状态。

## 8. 基于其他项目的优化说明

前端使用 `zen-ai-chat-ui`、`@inteye/llm-hub`、`@inteye/llm-hub-ui` 等第三方组件，语音合成为独立 TTS 服务。在当前代码基础上的主要优化：

- **场景聚焦**：围绕心理陪伴增加正念呼吸、能量站、预设情绪话题和温和文案，形成“倾诉—安抚—练习”的闭环。
- **情感 TTS 全链路**：情绪标签 Prompt、8 维向量、句子级合成流水线、预设/自定义音色、播放停止与状态提示。
- **多模态降级工作流**：图片不支持时自动 OCR 并回滚重发；语音输入支持 PTT 与锁定两种模式。
- **对话树交互**：编辑生成分支、撤回改叶节点、重新生成产生兄弟节点，树内可直接操作。
- **服务端稳定性与访问控制**：语音合成排队与超时控制、临时资源清理、试用访问代理与配额管理。
- **本地优先与云备份**：本地数据库持久化、空会话过滤、独立加密密码云备份。
- **体验细节**：主题切换、响应式、错误边界、图片查看器、OCR 进度、TTS 状态、减少动效适配。
